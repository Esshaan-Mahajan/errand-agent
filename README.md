# Errand Agent

A chat agent that arranges home-service errands: it clarifies missing details, compares providers, asks for approval before anything consequential, and recovers safely from tool failures. It runs entirely locally against mock tools, with no real providers or payments.

**Principle: the model proposes, code disposes.** The LLM understands requests and drives searches and holds. Booking, cancelling and rescheduling happen only in deterministic code, after the user confirms the exact details. The evals include models that misbehave on purpose, to show the guarantees don't rest on the model behaving.

## Quick start

Python 3.11 or newer. The offline paths need only the standard library and pytest.

```bash
python -m venv .venv
source .venv/Scripts/activate   # macOS/Linux: source .venv/bin/activate
pip install -e ".[dev]"
```

**Run the tests and regenerate the eval table:**

```bash
python -m pytest
```

**Chat with the side-by-side trace UI**, then open http://127.0.0.1:8765:

```bash
python -m errand_agent.web
```

**Chat in the terminal:**

```bash
python -m errand_agent.cli --scenario timeout-after-success
```

**Use the real model** by adding `--live` to either command, with `OPENAI_API_KEY` set. The default model is `gpt-6.1-terra`; use `--model` to change it.

Without `--live`, the agent runs on a rules-based stand-in. It's labelled in the UI and the trace, and it is not an LLM.

Try these:

- `Find a plumber for my kitchen tap this week, mornings only, under 1,500.`
- `Book the same electrician as last time, but not before 10 a.m.` (needs a past booking)
- `Remember my preferred area is Indiranagar`, then `What do you remember about me?`, then `Forget my preferred area`

The UI's scenario menu scripts failures such as `timeout-after-success`, `slot-taken`, `price-change-after-approval` and `prompt-injection`. **Provider cancels** and **Restart process** simulate those events.

## Model configuration

The live path uses `gpt-6.1-terra` at `low` reasoning effort through OpenAI's Responses API, with a manual tool loop, because each turn has to pass the context budget and guards. It sets `store: false`, so the conversation isn't kept for later retrieval. Encrypted reasoning items are replayed within a run but held only in memory, so they never reach traces, where forget couldn't scrub them. A refusal is reported to the user as its own outcome.

`--model` also accepts other OpenAI models. A `claude-` model ID switches to the Anthropic adapter ([anthropic_client.py](errand_agent/llm/anthropic_client.py)), which needs `ANTHROPIC_API_KEY` and `pip install -e ".[anthropic]"`. That adapter is tested against a fake server only.

## Known limitations

- **Re-asking is only partly enforced.** Code refuses `ask_user` for known fields, but a real model could still re-ask in plain text.
- **Approval is English-only by design.** Anything outside the grammar goes to the model, or re-shows the prompt, so the failure mode is an extra question.
- **The success-claim guard is a heuristic.** It's a second line of defence; real outcomes are always rendered by code from verified state.
- **Forget scrubs exact matches.** It removes the stored value everywhere, but can't catch a paraphrase in an old message.
- **Token counts are estimated** at chars/3. The trace logs this beside the API's real count, so check the margin in a live run.
- **Notification channels are recorded, not delivered.** "Urgent" is a decision in the trace and a tag in the UI; there is no real push.
- **Single process.** SQLite and per-user locks suit a local system, not a multi-instance deployment.
